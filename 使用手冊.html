Matt Pocock Skills

一套跑在 Claude Code / Codex 裡的工程 agent skill 集合。這份手冊教你怎麼裝、怎麼判斷該用哪一個、以及整套系統怎麼串在一起。

這是什麼/ 安裝/ 第一步/ 主流程/ 獨立工具/ 不知道用哪個/ 指令速查

01 · 這是什麼

一組 skill,不是一個框架

每個 skill 都是一份 SKILL.md,教 agent 用某種紀律做一件事——訪談你、寫 spec、拆 ticket、測試先行寫程式、審查 diff。它們刻意做得小、可組合,不會接管你的整個開發流程,你隨時可以只挑一個來用。

skill 分兩種。User-invoked 只有你自己打 /名稱 才會觸發;Model-invoked 除了你自己打,agent 判斷情境吻合時也會自己找上門。手冊裡每個 skill 名字旁邊都會標明是哪一種。

02 · 安裝

兩種裝法,擇一即可

兩者裝的是同一套內容,差別在於你要不要能自己改。裝兩份只會讓每個 skill 重複一次。

Claude Code plugin

訂閱式,唯讀,自動跟著更新。適合不想自己改內容的人。

/plugin install mattpocock-skills

skills.sh 安裝器

把可編輯的檔案複製進你的專案。適合想自己改、也適用 Codex 等其他 agent。

npx skills@latest add mattpocock/skills

03 · 裝完第一件事

每個 repo 先跑一次 setup

  1. 在目標 repo 裡執行 /setup-matt-pocock-skills。它會問你 issue 放哪(GitHub / Linear / 本地檔案)、triage 要用哪些標籤、domain 文件要存哪——每題都附建議答案,大部分情況答「好」就行。
  2. 沒跑這步之前,先別用 /triage、/to-spec、/to-tickets——這三個依賴這裡寫下的設定,沒設定就會用猜的。
  3. 其餘的 skill 不需要它。 /grill-me、/tdd、/prototype 這類工具跳過這步也能直接用。

04 · 核心心智模型

一條主流程,兩條匝道

多數工作都沿著同一條鏈走,從一個點子一路到 commit:

/grill-with-docs訪談 + 建詞彙
→
/to-spec整理成 spec
→
/to-tickets拆成 ticket
→
/implement測試先行建構
→
/code-review雙軸審查

五步走完,程式碼會被 commit 進目前的 branch。中途每一步都可以單獨叫出來用,不一定要走完全程。

兩條匝道併上這條主線

/triage 手上一堆 bug 回報、不是自己開的工作 → 先分類驗證,再交給主流程
/wayfinder 工作大到一次 session 裝不下、路線還模糊 → 先畫決策地圖,清完再交給 /to-spec

05 · 隨時可以單獨拿來用

不進主流程的獨立工具

不是每次都要走五步全程。這些工具解決的是單一、具體的問題,想到就用,用完就丟。

user/grill-me

只要訪談、不要留文件的版本。

user/handoff

把對話壓縮成交接文件,換 session 接手。

model/prototype

用完即丟的程式,回答一個設計問題。

model/diagnosing-bugs

難搞的 bug:先建紅燈迴圈,再診斷。

model/tdd

單獨的紅-綠-重構迴圈,不需要完整 spec。

model/resolving-merge-conflicts

卡在 merge/rebase 衝突時,依意圖逐 hunk 解決。

model/research

背景 agent 查第一手資料,交回附引用的筆記。

user/improve-codebase-architecture

每隔幾天掃一次,找可以加深的 module。

model/codebase-design

設計深 module 用的詞彙參考,不是流程。

model/domain-modeling

磨利專案用語,更新 CONTEXT.md 與 ADR。

user/teach

跨多個 session,把目前資料夾變成學習工作區。

user/writing-great-skills

自己要寫 skill 時的參考原則。

06 · 不知道該用哪個

問 router 就好

打 /ask-matt,描述你目前的情況——它不做任何實際工作,只負責告訴你該用哪個 skill、什麼順序執行。忘記整張地圖是正常的,這就是它存在的理由。

07 · 指令速查

User-invoked 指令一覽

以下都要自己打出來才會觸發,agent 不會自動找上它們。

指令用途先決條件
/setup-matt-pocock-skills每個 repo 第一次用其他 engineering skill 前,先跑一次無
/ask-matt不確定用哪個 skill 時的 router無
/grill-with-docs訪談 + 就地寫詞彙表與 ADR無
/grill-me只訪談,不留文件無
/to-spec把已對齊的討論整理成 spec 並發佈已跑過 setup
/to-tickets把 spec 拆成有 blocking 關係的 ticket已跑過 setup
/implement依 spec/ticket 測試先行建構,收尾前自動 review已有 spec 或 ticket
/triage把 tracker 裡的回報分類、驗證、寫說明已跑過 setup
/wayfinder大而模糊的工作,先畫決策地圖已跑過 setup
/improve-codebase-architecture掃 codebase,找加深機會,產出 HTML 報告無
/handoff把對話壓縮成交接文件無
/teach跨 session 的學習工作區無
/writing-great-skills寫/改 skill 的參考原則無
詞彙備註:Issue tracker、Issue、skill 名稱與指令一律保留英文原文,與 repo 本身的用語保持一致。完整清單見 README.md 與各 docs/<bucket>/<skill>.md。
