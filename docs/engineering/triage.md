## What it does

`triage` 讓你專案 tracker 上的 issue,沿著一個小小的 triage role **狀態機**往前走——分類、驗證說法、有需要就 grill 到成形,最後留下一份 ready-for-agent 的說明。

它絕不盲目貼標籤。每個經過 triage 的項目都恰好帶一個**分類(category)** role(`bug` / `enhancement`)與一個**狀態(state)** role(`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`),而且它*提出建議、然後等待*——它會附上理由告訴你它判斷的分類跟狀態,只有在你下達指示後才會動作。任何東西被推進 `ready-for-agent` 之前,它會先驗證這個說法:bug 要被重現,PR 要被 checkout 並跑過。

## When to reach for it

你打 `/triage`、用自然語言描述你要的東西來觸發它——agent 不會自己去找它。「給我看需要我注意的東西」、「來看看 #42」、「把 #42 移到 ready-for-agent」。

當你的 issue tracker 裡有一堆原始、還沒被評估過的回報,你想把它們分類、驗證,並轉成 agent 或人類可以接手的工作時就用它。想把一場已經談定的對話變成一份全新的 spec,改用 [to-spec](https://aihero.dev/skills-to-spec);想把一份既有的 spec 拆成 ticket,用 [to-tickets](https://aihero.dev/skills-to-tickets)。`triage` 是反過來的方向——它處理的是*已經*躺在 tracker 裡的東西。

## Prerequisites

`triage` 會讀寫你的 issue tracker,所以 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) 必須已經先設定好 tracker 與標籤對應。上面那些 role 名稱是**標準用語**——你 tracker 裡實際的標籤字串可能不同,而這份對應正是 setup 提供的東西。這份設定也決定了外部 PR 算不算一種請求來源,以及誰算是外部人士。

## PR 就是附帶程式碼的 issue

在 tracker 把外部 pull request 當成一種請求來源的地方,`triage` 會讓它們跑過*同一台*機器:同樣的分類 role、同樣的狀態、同樣的轉換——只是狀態這次是對照 diff 而不是對照回報來判斷。`ready-for-agent` 代表已經附上一份說明,agent 該對這段程式碼採取下一步;`ready-for-human` 代表可以合併了。自動探索只會找出外部 PR,但一個被明確指名的 PR,不管作者是誰都會被 triage。

## 先驗證,再寫說明

讓 `triage` 跟隨手貼標籤區隔開的那一步,是驗證。它會照回報者的步驟重現這個 bug,或是 checkout PR 並跑測試,然後回報結果:用一條程式碼路徑確認、驗證失敗,或資訊不足(這本身就是很強的 `needs-info` 訊號)。它還會跑兩項 codebase 檢查——**重複性**(這是不是已經做過了?那就是 `wontfix`)與**先前是否已被否決**(`.out-of-scope/` 裡是不是已經說不要了?)。一份確認過的驗證,能做出遠比用猜的更有力的 agent 說明。

## It's working if

- 它動到的每一項最後都恰好帶一個分類 role 跟一個狀態 role——絕不是零個,也絕不是兩個互相矛盾的狀態。
- 它會附上理由給你一個建議,然後等待,而不是自己重新貼標籤。
- bug 會先被重現、PR 會先被跑過,才會有東西進到 `ready-for-agent`。
- 它貼到 tracker 上的每一則留言,開頭都會有 `> *This was generated by AI during triage.*` 這句免責聲明。

## Where it fits

`triage` 是對你的 issue tracker 做的**週期性維護**——每當回報堆積起來就跑一次,讓佇列保持整齊、`ready-for-agent` 這個欄位保持可信。它站在 tracker 的最前端,在整條建置鏈的上游:它寫下的說明,正是 [tdd](https://aihero.dev/skills-tdd) 之後會接手實作的東西。當一個請求需要磨利時,它會靠 [grilling](https://aihero.dev/skills-grilling) 與 [domain-modeling](https://aihero.dev/skills-domain-modeling),一次一個問題地把它 grill 成形。它親近的鄰居是 [to-spec](https://aihero.dev/skills-to-spec)——那個是從一場全新對話把內容填進 tracker,`triage` 則是處理已經在裡面的東西。不確定該用哪個 skill 或流程時,[ask-matt](https://aihero.dev/skills-ask-matt) 會幫你導航。
